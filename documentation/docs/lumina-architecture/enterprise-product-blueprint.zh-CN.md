| --- | --- |

本文档同时承担四项职责：

1. 定义 Lumina 企业产品蓝图；
2. 登记现有能力和目标能力台账；
3. 固化架构边界与不可破坏的不变量；
4. 给出可以逐项执行的分阶段验收清单。

本文档是产品和工程基线，不是法律意见，也不代表当前版本已经达到商用发布条件。

## 2. 产品结论

Lumina 当前已经具备安装、升级、供应商配置、本地模型推理、项目与会话持久化、基础工具权限、Skills、Extensions 和 MCP 等产品骨架，但整体仍属于单机开发者验收版。

达到企业可用并接近 Codex，需要完成两个相互依赖的目标：

- 企业可用：可部署、可授权、可审计、可升级、可恢复、可离线、可治理；
- 项目级智能开发：能够理解整个项目、规划任务、操作多文件和终端、调用工具、展示差异、执行验证、处理中断并允许用户审核或回滚。

“接近 Codex”指接近其项目级开发体验和执行闭环，不复制其品牌、私有协议、账户体系或界面素材。

## 3. 用户可见内容统一使用简体中文

### 3.1 强制不变量

Lumina 面向用户展示的所有产品自有内容必须使用简体中文，包括：

- 安装器、卸载器、升级器和修复程序；
- 首次启动、登录、主页、项目、任务、会话、设置和帮助；
- 菜单、按钮、标签、提示、占位文字、空状态和加载状态；
- 错误、警告、通知、授权确认、权限说明和恢复建议；
- 供应商配置、模型管理、本地推理、MCP 中心和扩展中心；
- 任务状态、工具调用状态、验证结果、审计摘要和更新说明；
- 系统托盘、桌面通知、崩溃提示和数据迁移界面。

不得把英文作为缺失翻译时的回退语言。发布构建缺少简体中文文案时必须构建失败，不得在运行时回退为英文。

### 3.2 允许保留的技术标识

以下内容不是英文界面文案，可以按真实值保留：

- 产品和供应商专有名称，例如 Lumina、ChatGPT、Codex、Qwen；
- 标准和硬件缩写，例如 MCP、ACP、API、GPU、CPU、HTTP；
- 模型标识、供应商标识、文件路径、命令、代码、环境变量和网址；
- 用户输入、模型原始回答和外部网页原始内容。

专有名称不得单独承担操作说明。例如按钮不得只显示 `Retry`，必须显示“重试”；状态不得只显示 `Running`，必须显示“运行中”。

### 3.3 第三方错误与技术详情

- 第三方返回的英文错误必须映射为简体中文摘要、原因和处理建议；
- 原始错误只写入受保护的诊断记录，不直接作为界面提示；
- 用户主动导出诊断包时，可以包含错误码、协议字段和供应商原始响应，但必须提前说明可能包含技术标识；
- 未知错误统一显示中文兜底信息，并附可复制的错误编号，不显示英文堆栈。

### 3.4 中文界面发布门禁

- 默认语言和无配置回退语言均为 `zh-CN`；
- 发布构建只允许加载经过校验的简体中文产品文案；
- 禁止以源码中的英文 `defaultMessage` 作为生产回退；
- 建立用户可见字符串扫描，覆盖 React、Electron 主进程、Rust 错误、安装脚本和通知模板；
- 建立截图测试，覆盖正常、空、加载、失败、离线、权限拒绝和升级恢复状态；
- 日期、时间、数字、存储容量和排序遵循中国大陆习惯；
- 外部供应商或模型名称保持真实值，不进行错误翻译或机械改名。

## 4. 产品定位与目标用户

### 4.1 产品定位

Lumina 是以本地优先为基础、支持本地模型和企业批准云模型的项目级智能开发平台。桌面端负责交互和本地执行，核心运行时负责任务、权限、工具、模型、状态和证据，企业管理服务为可选组件。

### 4.2 目标用户

- 使用本地模型处理敏感代码的个人开发者；
- 需要统一供应商、模型和工具策略的软件团队；
- 需要离线或内网部署的企业；
- 需要审计、权限和数据治理的研发组织；
- 需要通过 MCP、Skills 和企业 API 扩展能力的平台团队。

### 4.3 明确不做

- 不把 Lumina 做成只有对话和单文件修改的聊天客户端；
- 不依赖旧产品服务器、遥测、更新源、账户或信任域；
- 不借用第三方 OAuth 客户端身份进行商业发行；
- 不在用户未配置、未授权时把项目内容发送给第三方；
- 不把未签名、无许可证或来源不明的 Skills、MCP、模型权重直接内置；
- 不在第一阶段引入不必要的微服务、消息队列或复杂分布式架构。

## 5. 关键用户旅程

### 5.1 本地模型项目开发

1. 用户打开项目目录；
2. Lumina 建立项目资料和允许访问的根目录；
3. 用户选择本地模型，界面明确显示“本地运行”、实际模型、GPU/CPU 和联网状态；
4. 用户创建开发任务并填写验收条件；
5. 智能体读取项目、制定计划并请求必要权限；
6. 智能体修改多文件、运行命令和测试；
7. 用户查看差异、验证结果和操作记录；
8. 用户接受、拒绝或回滚变更；
9. 软件重启后任务和证据仍可继续查看或恢复。

### 5.2 云供应商项目开发

1. 用户配置企业批准的供应商和模型；
2. Lumina 只用选定供应商的真实接口进行连接测试，不发送项目或会话内容；
3. 首次实际发送项目上下文前展示供应商、目标地址和数据范围；
4. 会话固定记录本次实际使用的供应商和模型；
5. 供应商不可用时显示中文错误和恢复方案，不静默切换到其他云服务。

### 5.3 MCP 安装与使用

1. 用户从受信来源或本地清单选择 MCP；
2. Lumina 展示来源、版本、许可证、哈希、签名、所需权限和网络目标；
3. 用户确认后安装，并在隔离环境中进行连接测试；
4. MCP 工具在会话中按策略授权；
5. 安装、配置、调用、升级、停用、卸载和回滚均有审计记录。

### 5.4 覆盖升级与恢复

1. 安装器识别旧版本并保留原安装位置选择；
2. 升级前备份配置、项目索引、会话、凭据引用和扩展状态；
3. 新版本完成数据迁移和自检后再切换为活动版本；
4. 失败时恢复旧版本和原数据；
5. 软件程序卸载不删除用户项目和受管数据目录。

## 9. 架构边界

### 9.1 桌面展示层

职责：展示中文界面、收集用户输入、呈现任务状态和证据。

禁止：

- 直接读取任意文件或启动任意进程；
- 直接保存供应商密钥；
- 绕过应用服务直接调用模型或 MCP；
- 把页面内存状态作为任务事实源；
- 直接展示第三方英文错误或 Rust/JavaScript 堆栈。

### 9.2 应用编排层

职责：协调项目、任务、会话、审批、恢复和用户意图。

约束：

- 所有长任务具有稳定任务编号和状态机；
- 重试创建新运行记录，不覆盖已经结束的运行历史；
- 中断恢复以持久化检查点为依据，不猜测执行结果；
- 批量操作前生成范围和影响预览。

### 9.3 权限与策略网关

职责：成为所有文件、命令、网络、浏览器、桌面、模型和 MCP 操作的统一入口。

约束：

- 默认拒绝超出项目允许根目录的访问；
- 默认拒绝未配置的第三方网络连接；
- 危险操作必须显示中文影响说明并获得明确授权；
- 管理员策略优先于用户本地放宽设置；
- 每次决策都产生审计事件。

### 9.4 模型供应商网关

职责：统一适配本地推理、官方供应商和自定义兼容接口。

约束：

- 供应商真实标识、模型标识、接口路径和 OAuth 标识不得机械改名；
- 每个请求记录实际供应商、模型、本地/远程属性和目标地址；
- 本地模型失败不得静默改用云模型；
- 连接测试不得携带项目文件和会话正文；
- 供应商适配器不得拥有项目、任务或审计事实状态。

### 9.5 执行与工具运行时

职责：受控执行文件、终端、Git、HTTP、浏览器、桌面和文档工具。

约束：

- 每个工具声明输入、输出、权限、超时、取消和幂等属性；
- 工具执行前后都经过策略网关；
- 大型输出作为产物保存，不无限写入会话上下文；
- 取消和超时必须真实终止子进程或操作；
- 工具不得自行选择新的第三方目的地。

### 9.6 扩展运行时

职责：加载经过批准的 Skills、Tools、MCP、Hooks 和 Workflows。

约束：

- 扩展不是核心运行时的一部分；
- 每个扩展具有来源、版本、哈希、签名、许可证和权限声明；
- 脚本运行在受控进程和目录中；
- 扩展失败不能破坏核心项目数据；
- 可禁用、卸载和回滚到前一版本。

### 9.7 数据与凭据层

职责：保存项目元数据、任务、会话、审计、索引、产物和凭据引用。

约束：

- 程序目录、受管数据目录和用户项目目录彼此分离；
- API Key、OAuth Token 和 MCP Secret 不以明文进入普通配置和日志；
- 数据库变更必须有版本迁移、升级测试和回滚策略；
- 删除操作明确区分“删除索引”“删除 Lumina 数据”和“删除用户项目”；
- 软件卸载默认不删除用户项目或受管数据。

### 9.8 旧数据迁移边界

- 旧数据迁移器是独立可选工具，不链接进入主运行时；
- 只读旧数据源，先复制到暂存区，再进行转换和校验；
- 迁移失败不修改原数据；
- 旧信任记录、签名和标识不能直接进入 Lumina 信任域，必须重新签发；
- 主产品不保留旧产品遥测、更新、协议、存储命名空间和服务器依赖。

### 9.9 标准协议边界

- MCP 和 ACP 作为外部标准兼容层保留，不视为旧产品私有协议；
- Lumina 的项目、任务、权限、审计和扩展契约由 Lumina 自有版本化协议定义；
- 标准适配器只能在边界转换，不得把外部协议对象直接作为核心领域事实源；
- 所有 Lumina 自有扩展方法使用 Lumina 命名空间并提供版本迁移策略。

## 11. 架构决策记录

### DEC-001：采用 Lumina 原生领域契约

- 结论：保留 MCP、ACP 等开放标准兼容，但项目、任务、权限、审计、扩展和发布使用 Lumina 自有契约；
- 否决：继续把旧产品内部对象改名后作为 Lumina 核心；
- 原因：改名不能消除协议、状态、信任域和后续演进耦合；
- 回退：边界适配器可临时兼容旧数据，但不得进入主领域模型。

### DEC-002：商业版用户界面只使用简体中文

- 结论：默认语言和回退语言均为简体中文；
- 保留：技术标识、供应商名称、模型标识、路径和命令按原值展示；
- 否决：缺少翻译时回退英文；
- 原因：这是明确产品要求，且可以通过构建和截图门禁验证；
- 演进：未来如增加其他语言，必须作为完整语言包交付，不能削弱简体中文基线。

### DEC-003：高风险工具能力必须经过统一策略网关

- 结论：文件、终端、网络、浏览器、桌面和 MCP 共用一个策略决策入口；
- 否决：各页面或扩展自行弹窗、自行判断权限；
- 原因：分散权限会产生绕过、规则不一致和审计缺口；
- 前置：策略网关和审计完成前，浏览器与桌面控制不得标记为正式可用。

### DEC-004：本地优先，不静默切换云端

- 结论：本地模型与云模型具有明确边界，失败时只在用户确认后切换；
- 原因：保护代码和会话数据，确保用户能确认实际使用的模型；
- 降级：GPU 不可用时允许降级 CPU，但不得把本地任务自动发送到云端。

### DEC-005：扩展包与核心产品解耦

- 结论：Skills、MCP 和工作流以签名扩展包安装；
- 否决：把第三方技能仓库直接复制进核心安装包；
- 原因：许可证、更新节奏、权限和故障边界不同；
- 条件：无明确商业分发许可的扩展不得随商业安装包发布。

### DEC-006：企业管理服务保持可选

- 结论：单机版不依赖企业服务即可使用本地项目和模型；
- 原因：满足离线、内网和个人开发场景；
- 扩展：企业服务只负责身份、组织、策略、配额、设备和汇总审计，不接管本地任务事实源。

## 16. 实施顺序与依赖

```text
简体中文与领域契约
        ↓
权限、凭据、网络、审计、升级
        ↓
项目任务、多文件、终端、Git、本地模型

浏览器、桌面和高级工具
```

- 数据迁移和自动回滚未完成，不启用无人值守自动更新；
- 本地模型项目工具调用未通过，不宣传“本地智能开发”；
